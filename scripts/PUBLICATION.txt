AeroSense publication preparation
================================

The canonical website source is this aerosense-wiki directory. Run all commands
below from this directory. No parent-workspace scripts, backups or upload copies
are required. This workflow does not upload files or push repository changes.

1. Refresh the local publication inventory:
   node scripts/audit-publish-assets-v7.cjs

   Output goes to igem-upload/publication/. Inspect the missing-reference list,
   the local dependency inventory, and the external official-media URLs.
   Resolve genuine missing local dependencies before preparing a release.

2. Prepare the file list:
   python scripts/prepare_publication_manifest_v7.py

   This validates the inventory and updates publication-files.json. Original
   research sources are retained separately from publication dependencies:
   an unlisted research file is not permission to delete it.

3. Create deployment output only when it is needed:
   python scripts/build-publication.py

   This creates public/, copies the local manifest files, and creates a
   directory-index route for each root page using the /nthu/ team base.
   --routes-only prepares the HTML route files without copying assets.

4. Keep both compiled browser files and their editable sources. In particular,
   keep game/apps/wiki-client/dist/, the homepage bundles and all inputs listed
   in home-bundle-sources.json. The game package manifests and lockfile restore
   build dependencies when a new build is needed.

5. The official media receipt and verified URL mapping are retained under
   igem-upload/. Migrated images already use their official URLs. Pending
   videos and other resources still referenced locally must stay until their
   official replacements are usable and the references have been updated.

6. The separate zenodo-release folder is the single location for research
   documents, code and original data. It has not been published. Website
   availability entries say "Zenodo (publication pending)" without a URL.
   Do not restore research copies into the website or publish the Zenodo
   folder with the website. Add the final Zenodo URL after publication.

7. Deployment remains separate from preparation. Verify the official host's
   team base, extensionless routes, media playback and linked downloads after
   deployment. A successful local preview does not verify server routing.
