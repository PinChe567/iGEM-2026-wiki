# Docking 與捕捉蛋白假說

## 查核狀態

2026-10-05 檢查的本機釋出包沒有專案 docking 結構、PDBQT、配體、pose 或執行紀錄。公開 repository 的 `ca8b47014315f4ffe4431a3b04874816410cafcf` 完整樹共有 1,201 項，未找到 docking／OBP／Vina／PDB 紀錄；唯一 `docker-compose.yml` 命中與分子 docking 無關。這只是本次搜尋範圍，不能據此說團隊在別處一定沒做過。當前 Model／Description 頁也沒有特定 OBP 身分與 docking 結果。

「OBP」本身不能辨認是哪個分子。要把捕捉蛋白寫成元件前，需要物種、確切名稱與 accession、完整序列、預定構築、結構來源／chain 及修改。如果這裡 OBP 指 odorant-binding protein，必須把假定捕捉功能與 OR／Orco 感測複合體、GCaMP 報導蛋白分開。不能從氣味名稱猜蛋白，也不能把另一篇文獻的例子當成本團隊構築。

## Docking 可以貢獻什麼

Docking 可在明確結構準備與打分方法下，提出可能的結合構型，或幫少量蛋白－配體假說排序；不能直接量 Kd、受器活化、傳輸速度或細胞反應。[Vina 官方 FAQ](https://autodock-vina.readthedocs.io/en/latest/faq.html?highlight=exhaustiveness)建議在可能時，利用已知活性配體或結合結構做目標專一評估。[官方教學](https://autodock-vina.readthedocs.io/en/stable/docking_basic.html)展示搜尋隨機性及 exhaustiveness 的影響，也提醒不同打分函數不可直接比較。這些是方法來源；其範例分數不是 AeroSense 結果。

本包不提供虛構的蛋白－配體排名、能量或親和力，因為必要輸入與結果尚未提供。一張看起來合理的分子圖，不能替代可追溯運算。

## 若已有結果，最低需要哪些紀錄

| 項目 | 內容 |
|---|---|
| 生物問題 | 明確蛋白及配體、與介面有何關係、結果能改變哪個決策 |
| 蛋白輸入 | accession／序列、結構來源及日期、chain、預測或實驗結構、可信度／覆蓋率、缺失區域與準備方式 |
| 配體輸入 | 身分、立體化學、來源、質子化／互變異構假設、準備後座標 |
| 執行設定 | 軟體／打分函數／版本、搜尋盒中心與大小（Å）、種子、exhaustiveness、可動區、水／輔因子處理 |
| 原始輸出 | 完整 log、保留構型及分數、失敗案例；不只最佳截圖 |
| 檢查 | 重複種子、接觸與構型合理性、有條件時做 redocking／已知對照；沒有驗證結構也要註明 |
| 解釋 | 只在指定設定下比較分數，不改寫成實測 Kd 或活化證明 |
| 重現 | 授權、雜湊、環境、一條可執行命令及其實際輸出 |

Model 主頁放簡短問題、方法、可支持結論及不確定性；完整輸入／log／pose／表格／重現程式放附錄。若有真正受器反應或結合實驗，放實驗 Results 與 protocol，再交叉連結，不混成同一種證據。

## 捕捉不等於一定加快細胞收到氣味

只以單一位點平衡作概念例子，可寫 `B = B_total × C_free / (Kd + C_free)`。它區分自由態與結合態，不是對特定 OBP 擬合，也沒有拿來產生本次氣體 CFD。結合可能改變總吸收、緩衝、釋放與殘留；較好的 docking 分數無法決定細胞介面上哪一個作用占優勢。不要把 docking 分數換算成數值 Kd，再當成實測傳輸參數使用。

目前氣體模型描述介面濃度，沒有捕捉蛋白化學。深入液相邊界案例則刻意不含蛋白促進及混合。蛋白機制可以是下一個模型問題，但需要自己的身分、參數與獨立證據。目前機械釋出不因此新增蛋白、膜或必買元件。
