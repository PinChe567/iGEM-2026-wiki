# Wiki 放置與行動規劃

## 核心安排

**Hardware 放工程決策與重製方法；Model 放模型方法、數值查核及解釋；Description 放整體故事。** 主要方法、關鍵圖表與結論直接放在相應主頁。附錄保存完整程式、原始表格、參數及下載資料，不應成為評審唯一能找到證據的地方。

目前成果是可重現的計算設計，以及準備好的硬體測試流程。它還不能證明整機已製造成功、氣味已快速抵達細胞、氣味分類器已在 AeroSense 上驗證，或列印井具有無菌／細胞相容性。清楚交代這些界線，不會降低工程價值；反而能讓讀者判斷哪個結果真的支持哪個決策。

## 主頁內容安排

### Hardware 建議六個重點區塊

1. **需求與限制：** 四井、共享 PD、可更換、零件少。小型化不等於續航與可攜使用已驗證。
2. **怎麼組成：** 目前整機／爆炸 CAD、PCB 接孔與一體風扇座；圖說明確寫 CAD。放短版零件／樹脂表，完整 BOM／手冊用下載連結。
3. **光學如何影響設計：** 井底光圖與 LED×來源井矩陣。只下三個結論：條件式收光非零、照光不均勻、仍有井間混合。連至 Model 的方法與訊號污染。
4. **氣路如何影響設計：** 導流台／開放腔室比較、18 點孔板掃描、固定 STL 的 Q×D 操作範圍。說明零件、清潔與氣流分布的取捨，不說「最完美」。
5. **如何操作與重製：** 真正 UI 或標示 DEMO 的畫面，設定／校正順序、STL／BOM／firmware。編譯成功不等於 PCB 已能量到螢光。
6. **還缺什麼證據：** blank／螢光標準、實測混合矩陣、氣液介面與後續細胞暴露、他人照手冊組裝。只有取得原始紀錄後才填上測量結果。

### Model 以問題分區

新增 **Read：物理量測模型**，原本 **Decode：SNN 基準** 保留獨立。

- `optical-transport`：光學幾何、非正中央 PD、濾片與接受角、能量帳、細胞層假設、種子與誤差。
- `detector-interference`：理想／收到／疊圖／殘差、四通道偏差、OD／環境光掃描。影片用來解釋，不當作主要定量證據。
- `gas-and-liquid-transport`：分清速度、分子擴散、液面上方濃度與底部細胞暴露。主題先聚焦氣體到氣液介面；深入液相／PDMS 邊界模型放附錄。蛋白促進吸收仍是未測假說。
- `model-to-build`：問題 → 計算 → CAD／操作決策 → 下一個測試，每列連回 Hardware。
- `molecular-hypotheses`：若要提 docking／OBP，在未有檔案前只寫假說與資料要求，不放看似已完成的排名或結合構型。
- 原 `network`、`training-evaluation`、`performance`、`limitations` 不混入光學模型的誤差棒，也不以合成測試支持 SNN 的 F1。

### Description 只保留簡潔系統圖

氣體樣本 → 共用氣室 → 液體／細胞 → 螢光 → PD／ADC → 手機與資料分析。傳質與生物反應標明待驗證介面。若畫 OBP，把它放在明確分開的未來假說分支，不畫成目前已安裝元件。

## 不能被下載檔掩蓋的重點

| 現有結果 | 可說明 | 不可推論 |
|---|---|---|
| NE 條件式綠光 0.593 ± 0.035 nW，三種子 SE | 指定假設下存在抵達有限 PD 的光路 | 實測功率、細胞訊號一定夠、偵測極限 |
| 井底 CV 約 46.2%；目標井貢獻約 88.6–90.9% | 仍須校正照光及光學混合 | 平底就均勻、四個頻率就是四個獨立生物井 |
| 預設合成情境振幅偏差 2.63–3.52%、波形 AC SINR 23.40 dB | 同頻污染會通過解調 | 真實 PCB 精度或雜訊 |
| 導流台細網格動量指標降約 36.1%、P95 速度降約 20.1% | 該比較下方向性流動指標改善 | 湍流、保護細胞、全域最優 |
| 細網格交換 CV 約 0.0098 → 0.369 | 改善伴隨分布不對稱的取捨 | 氣味濃度均一 |
| 1 mL/min 基準液面附近氣相 t90 約 150 s；條件式 3 mL/min 候選的名目最慢 t90 約 50 s | 固定 CAD 的 Q×D 掃描選已運算操作點；2.5 mL/min 約 60.04 s 是數值邊界 | 已抵達底部細胞、細胞損傷門檻或蛋白促進吸收 |
| 網站 SNN F1 0.868 | 已報告的單種子、混合批次金屬氧化物基準 | 本套細胞資料、抗漂移或本包已重現的成績 |

無蛋白促進傳輸、無液體混合時，100 µL、假設 D_liquid=10⁻⁹ m²/s 的代表性液相計算為底部 t90 約 22.85 小時。詳細結果放附錄，主頁保留一句介面不等於細胞暴露的限制即可。這不是實際受器反應時間，也不代表氣體 CFD 無效；它用來提出值得量測的傳質問題。

## 與 2026 評分問題的關係

已查核的官方 [Special Awards](https://competition.igem.org/judging/special-prizes) 中，Hardware 重點是需求、使用者回饋、功能與可重製；Model 重點是方法、理解／設計價值、相關資料及他人能否借鑑。本次未查到 overgraduate 專用的額外數值門檻，不應捏造「達到某個 SNR 就會得獎」。

實際做法是：讓每個模型連到明確工程選擇；把數值自測與實機量測分開；讓另一個人照文件重現一張圖或完成組裝。合作可以發現電路問題、難懂的步驟或漏列的工具。紀錄日期、任務、設備、觀察、修改及重測結果。討論、推薦或只填問卷不能取代整機功能證據。Cycle 5 在真正有人依手冊完成任務前，維持「規劃中」。

## 正式 Wiki、GitHub 與附錄

2026 官方獎項頁明列 `/hardware` 與 `/model` 標準頁。主張與核心證據留在正式隊伍 Wiki；GitHub Pages 可作預覽／鏡像，不等於正式提交。

目前 Team Wiki 政策頁透過工具只回傳 JavaScript 殼，無法據此聲稱所有細節都已確認為 2026 規則。[2025 官方 handbook](https://static.igem.org/websites/competition/2025/judging/2025judgehandbook.pdf) 在此是**標明年度的備援**，支持可封存、自包含的 iGEM 專案紀錄；不把它冒稱 2026 新規則，也不推測罰則或截止時間。正式上線前應在隊伍平台核對最新要求。

保守且容易重現的做法：程式與固定資料放隊伍 iGEM GitLab；可支援的圖／文件走 iGEM 上傳平台；競賽影片用 iGEM Video Universe；互動頁所需 JavaScript 與資料也由允許的 iGEM 設施提供。GitHub 可保留鏡像，但主證據不能依賴外部 API、會變動的 notebook 或鏡像是否在線。一般論文參考連結與頁面執行時載入外站資源不同，不要把它誤寫成「禁止任何外站引用」。部署後使用官方 External Content Check。

附錄索引要有日期、程式／依賴版本、資料來源、假設、重現指令、檔案雜湊、授權與貢獻者。內容包括光學／氣流／膜模型的完整原始表、程式、圖說、CAD 原始碼、八個指定 STL、BOM、手冊與 firmware。主頁每個重要結果連到對應來源，不要只放一個沒有導覽的 ZIP。

## 時間有限時的順序

1. 先同時替換 Hardware 舊幾何、數字、圖及下載，避免新舊混用。
2. Model 加物理模型，保留 SNN 獨立範圍；主頁說清楚氣液介面與細胞暴露的差別。
3. 用已完成成果建立附錄索引，主頁仍要看得到關鍵方法及結果。
4. PCB 到手後照現有精簡測試表做，只有有日期、原始檔、單位、對照及實際重複次數的數據才能升級為實驗證據。
5. 實際手冊試用後再寫 Cycle 5 的觀察 → 修改 → 重測；之前只放流程與空白表單。
6. 最後才是資料齊備的 docking／OBP 探索。它的優先度低於基本硬體證據缺口。

本規劃不宣稱新增任何實驗。時間不夠時，清楚的負面／未完成結果比無根據的成功敘事更有用。


## 組裝回饋在不同頁面的分工

研究方法、匿名觀察與組裝任務結果留在Hardware，問題→修改→重測放Engineering Cycle5。Entrepreneurship連結目標使用者需求／採用障礙；Education須有實際教學目標、對話與學習證據，單純易用性問卷不自動滿足兩者。同一批受試者不能重複當成獨立研究。[完成清單](../../07_validation/Completion_Plan_ZH.md)列剩餘工作，[標準液／細胞說明](../../07_validation/Fluorescence_and_Cell_Test_ZH.md)區分光學驗證與生物成果。
