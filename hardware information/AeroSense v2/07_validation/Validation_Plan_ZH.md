# 一次無細胞實驗：從四井螢光到手機結果

這是PCB到手後的主要驗證實驗，目標是用一次連續工作流程，檢查「讀到螢光、背景可校正、濃度反應合理、四井對應可辨識、資料能匯出」。預估熟悉操作後約60–120分鐘；首次燒錄與裝配另計。所有實測表目前空白。這個實驗不能單獨證明氣味辨識、細胞存活或氣體抵達細胞的時間。

## 先做10–15分鐘必要確認

1. 斷電試裝，確認不必硬壓PCB、插頭可插入、風扇不磨框。四井先離開PCB，以清水和紙巾看有無可見漏液，再擦乾。
2. 由熟悉電路的人按原理圖確認電源、3.3 V和ADC reference。J2 USB-C是供電／充電，J3才是3.3 V UART；按操作手冊完成韌體與網頁燒錄。
3. 先全關LED，取得有效原始ADC區塊。若讀值卡在上下軌、時序QC失敗或元件異常發熱，暫停；不能靠扣背景修好截波。確認供電與ADC後，才由負責人解除BOARD_VALIDATED鎖。
4. 無細胞、低duty短時間逐燈確認D1–D4對應哪個井，填入實際NE／NW／SW／SE對照。按一次手機停止，確認關燈。可借波形工具時順便看四個頻率；不能量到的時序項目留「未量測」。

以上不是另開一串研究實驗，而是避免後面的漂亮曲線其實來自接錯、飽和或方向錯誤。若10–15分鐘內發現故障，排除故障的時間不能跳過。

## 材料與固定條件

使用實驗室已有的穩定綠色螢光標準，例如合適的fluorescein標準液；空白、C與0.5C使用同一介質及pH。C代表本次選定的工作濃度，不是預先假造的GCaMP濃度或偵測極限。依標準液標籤／實驗室現有流程配製，記錄名稱、批號、實際濃度和pH。原廠資料指出fluorescein強度受pH影響，因此不能用不同pH的水做濃度比較。[原廠標準液文件](https://documents.thermofisher.com/TFS-Assets/LSG/manuals/mp36915.pdf)

四井每井100 µL、同一井組與濾片、固定全四燈duty和頻率、固定室內照明。先用一組C試讀：若截波或幾乎讀不到，可調整工作濃度／LED設定，之後重新開始完整空白與正式系列，保留試讀紀錄。正式系列開始後不再為了好看的曲線改設定。

不需為這次螢光試驗新增氣體感測器。若開啟供氣，量到的流量與泵位置要記錄，整組保持一致；它仍不能驗證CFD的濃度曲線。新的固定外殼供氣建議在Flow_Operation報告。

## 唯一實驗流程

每個狀態收5個不同、有效的2秒區塊；組間等待沿用UI允許值。每次改狀態，先停止排程，再換液、關蓋並填入下表的「條件標籤」。UI校正用的「條件代碼」則保持同一個裝配／設定識別，不因每個濃度標籤而改動。

| 標籤 | 放什麼 | 做什麼 |
|---|---|---|
| DARK | 四井空白，LED關閉 | 保存暗態及原始ADC；先確認QC。 |
| B_CAL | 四井空白，四LED開啟 | 收5組，作「亮燈空白」校正；之後凍結這組校正。 |
| B_CHECK | 相同空白，再量5組 | 獨立檢查背景；不加入校正集合，避免用自己扣自己。 |
| NE_C | 只有NE井為C，其他井空白 | 收5組四頻道原始I/Q。 |
| NW_C | 只有NW井為C，其他井空白 | 同上。 |
| SW_C | 只有SW井為C，其他井空白 | 同上。 |
| SE_C | 只有SE井為C，其他井空白 | 同上。 |
| ALL_HALF | 四井都是0.5C | 收5組，作濃度反應的中間點。 |
| ALL_C | 四井都是C | 收5組；可同時取得有效螢光相位參考。 |
| ALL_HALF_REPEAT | 再配／換回四井0.5C | 收5組，檢查換液及時間造成的差異。 |

換到下一個單井狀態前，依實驗室對該標準的洗滌流程清除前一井殘留；若樹脂明顯吸附、洗後仍發光，記錄並停止把它當成乾淨空白。不要把殘留訊號刪掉。移液器與現成耗材即可，不新增列印件。

每一組剛完成時，UI會保存當時的條件標籤與註記。最後匯出完整JSON；下載至少一組空白及一組C的原始ADC。確認匯出檔含以上標籤後，才清除瀏覽器資料。原始資料、錯誤／失敗區塊和校正記錄一併保留。

## 分析只看三張圖

1. **0、0.5C、C反應圖：** 使用原始I/Q，先扣獨立B_CAL的複數平均，再投影到本次ALL_C的實測相位。畫平均和技術區塊SD，保留未平滑值。半濃度應大致接近一半訊號，並檢查ALL_HALF_REPEAT漂移。
2. **4×4單井矩陣：** 每次只有一井發光；列是實際LED方向，欄是發光井。對每列正規化，與「均勻標準液」蒙地卡羅結果比較比例及主導井。不能拿此矩陣代替井底細胞模型，也不自動拿來做細胞解混。
3. **獨立空白校正前後圖：** 用B_CHECK看穩定背景偏移是否減少。扣掉固定背景不會消除隨機雜訊；不能把平均歸零宣稱為SNR無限大。

### 一個重跑指令

安裝現有Python分析依賴後，在07_validation執行：

```text
python -m pip install -r requirements.txt
python quick_check.py --input my_session.json --mapping SW,SE,NE,NW
```

`--mapping`依序代表D1、D2、D3、D4的**實際觀察方向**；上列只是命令範例，不可未量測就照抄。程式要求新版硬體中繼資料與按時間排列的原始記錄，拒絕DEMO、重複區塊、混用裝置／設定或不足5組的狀態，並獨立檢查截波／時序欄位。ALL_C相位參考太弱時會停止分析。輸出在measured_results/single_experiment，含三張圖、取得設定、區塊ID、數值、排除記錄與圖說。`--self-test`只檢查程式，不會產生實驗結果。

## 開始前先固定的開發門檻

這些是本次原型的暫定工程門檻，不是iGEM規定或正式檢出限：所有正式區塊無截波且時序QC通過；每個通道的「0.5C平均投影−獨立B_CHECK平均投影」須大於B_CHECK區塊SD的5倍；訊號B_CHECK<0.5C<C；半／全濃度比介於0.35–0.65；兩個螢光等級的技術CV≤10%；重做0.5C的平均漂移≤10%；各LED最大反應來自預期井，列正規化對角項>0.60。全部投影已扣除一次B_CAL；檢出餘裕再與獨立空白平均相比，可避免空白整體漂移卻誤判通過。這不是把儲存的反應曲線再扣一次背景。

每項分開報告，不以一個總分掩蓋失敗。5個區塊是技術重複，不是5次獨立生物實驗。低訊號时CV不穩定，保留絕對SD與原始值；接近閾值時不能聲稱精確通過。若未通過，先依失敗種類檢查映射、背景漂移、濾片或飽和；不要用神經網路把失敗藏起來。

## 可以在Wiki寫到哪裡

通過後可寫：「在指定100 µL螢光標準條件下，裝配好的原型完成手機控制、四頻率讀取、獨立亮燈空白校正與資料匯出，量得濃度反應及單井傳輸矩陣。」附實物照、三張圖與原始JSON。沒有量到的項目仍留空。

這不證明GCaMP細胞反應、VOC選擇性、實際氣體濃度到達曲線、無菌或長時間培養。螢光標準的絕對亮度也不能直接換成細胞靈敏度。

## 剩餘時間怎麼用

裝配與燒錄先完成；請2–3位沒參與設計的人照手冊裝配，記錄耗時、卡住處與協助，填既有問卷，修改最嚴重的1–2項後再試一次。這是使用者回饋循環，和上面的光學实验分開標示。

若wet lab已有成熟的受體／GCaMP細胞與刺激流程，再做一次同批樣本的設備／既有讀取儀器對照：保留既有陰性及陽性對照，記錄氣體開始時間、流量與訊號。比較未任意平移的時間曲線及事先定義的ΔF/F0；若wet lab是液體刺激而本裝置是氣體刺激，只能比較有條件的趨勢，不能假定劑量相同。共享氣路下四井收到同一股氣體，不能把它們當成四個獨立氣味曝露。蛋白輔助捕捉目前仍是待驗證機制。
