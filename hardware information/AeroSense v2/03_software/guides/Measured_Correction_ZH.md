# 實測背景校正與顯示平滑

新版會在 I/Q 向量上扣除**實際量到的亮燈空白**，不添加任意抵消波形，也不宣稱能去掉未知同頻干擾。ESP32 仍輸出原始 I、Q 與幅度，校正在瀏覽器完成；原始值與校正值分開保存。軟體測試不等於已燒錄或已通過實板驗證。

## 三種對照不要混在一起

| 對照 | 怎麼準備、拿來做什麼 |
|---|---|
| 亮燈空白 | 無螢光、無細胞，使用相同液量、well、濾片、duty 與光學裝配；四燈運作。量測可重複的電子與光學背景，裡面已經包含暗背景。 |
| 螢光相位參考 | 同一量測與光學條件下的穩定螢光標準。扣空白後的平均向量決定各通道的參考方向；這不是濃度校正，也不是 GCaMP 靈敏度證明。 |
| 活細胞 F0 | 未刺激細胞的基線，供 ΔF/F0 使用。它必須另外量，不能當成雜訊扣掉。 |

暗訊號仍用於實板最初的 ADC／時序檢查。新版路徑只扣一次亮燈空白，**不再加扣暗訊號**。關閉新版校正時，原來的暗訊號幅度正規化仍可使用。

## 最短操作流程

1. 完成操作手冊的電源、ADC 與時序檢查。
2. 連上手機 UI。
3. 輸入包含板、well、液量、濾片與 duty 的 Condition ID。
4. 放入預定液量的不含細胞、無螢光空白。
5. 將 Current sample label 設為 B_CAL。
6. 按 1. Collect illuminated blank。
7. 保持網頁開啟，直到收滿五個有效空白區塊。
8. 放入穩定螢光標準。
9. 將 Current sample label 設為 PHASE_REF。
10. 按 2. Collect fluorescence phase reference。
11. 等待五個有效參考區塊。
12. 檢查各通道參考狀態。
13. 勾選 3. Enable measured blank subtraction。
14. 初次比較將 Display smoothing τ 設為 0。
15. 放入測試樣本。
16. 設定該樣本的 Current sample label。
17. 保持取樣設定不變並量測樣本。
18. 匯出 JSON。
19. 匯出 CSV。

確認：收集器須收到對應裝置確認與有效紀錄；按到按鈕不等於完成校正。弱參考無法定義相位投影，但校正幅值可能仍可用。細胞正規化須在光學校正後另外收五個未刺激細胞 Baseline；合格標準刺激另收 Reference。更新空白或相位校正會使先前 F0 與 Reference 失效。不要再扣一次 dark。更換實物樣本不會改變 DEMO 合成資料。

## 怎麼算、哪些事情做不到

每個頻率定義 `C=I+iQ`；韌體用 `I=2 mean(v cos θ)`、`Q=2 mean(v sin θ)`，單位為正弦基本頻率的峰值伏特。此 Q 符號與部分相量慣例相反，但此處所有校正使用同一輸出慣例。

空白平均 `B=mean(C_blank)`，扣除為 `C_corrected=C_sample−B`，不是直接做兩個幅度相減。以螢光參考定義方向 `u=(mean(C_reference)−B)/|mean(C_reference)−B|`，有號投影 `P=Re(C_corrected×conjugate(u))`。垂直分量與校正幅度也保留。相位改變會讓投影變小，即使真正幅度不變；訊號足夠大而相位偏離超過 15° 時會警示。15° 是暫定工程診斷，不是已驗證生物門檻。

新版 F0 與樣本正規化使用**未平滑的有號投影**。F0 必須大於「實測組間變動與一個名目 ADC 刻度中較大者」的五倍；標準刺激的分母還會納入標準刺激本身的組間變動。重複的 F0／標準刺激記錄 ID 會被拒絕。相位參考則以平均值的標準誤並加同樣 ADC 刻度下限作保守檢查。這是避免不穩定相除的內部防護，不是量到的 LOD；平均量測在原理上可能解析小於單一原始 ADC 刻度的變化。

扣空白移除的是估計的固定背景向量，不會移除光子散粒雜訊或隨機電子雜訊。空白平均本身也不精準；獨立樣本與空白估計的變異相加，而且空白的不確定性會共同留在所有校正結果中。繼續平均樣本不能消除這個共同誤差。若同頻污染在校正後改變，它仍留在結果中；單一複數讀值無法分離兩個未知的同頻來源。

I/Q 向量與窄頻平均的原理參考 [SRS《About Lock-In Amplifiers》](https://www.thinksrs.com/downloads/pdfs/applicationnotes/AboutLIAs.pdf) 與 [Zurich Instruments 同步檢波原理](https://blogs.zhinst.com/en/resources/principles-of-lock-in-detection/)。此處的複數扣背景與投影是對實測向量的線性運算，不代表這些儀器替 AeroSense 背書。程式不會自動套用模擬的串擾矩陣。

## 顯示平滑的時間常數

先校正 I/Q，再以 `alpha=1−exp(−Δt/τ)`、`Y_new=(1−alpha)Y_old+alpha C_corrected` 作一階 EMA。

Δt 來自設備的單調遞增取樣中點時間，不用手機輪詢或網路抵達時間。預設 τ=2 秒，0 表示關閉，可填 0–120 秒。第一個有效組直接初始化；重複讀同一組不會再平均。無效資料、校正／設定改變、重開機、改 τ 或重新整理頁面會重設；設備時間不遞增則拒絕處理。

已初始化的一階系統遇到持續階躍時，理想連續反應約 2.303τ 到 90%、約 3τ 到 95%；真正稀疏組間更新依上式。若每組 2 秒、關燈等 3 秒，Δt 約 5 秒，τ=2 秒的平滑其實很少。拉長 τ 可降低獨立變動，但會延遲變化。這是在原本 2 秒 I/Q 矩形平均之後的額外平均，不是新增 ADC 濾波器，也不是量到的類比頻寬。不要把平滑後的組當作獨立重複，也不能用它掩蓋短暫反應、截波或漂移。時間常數與濾波階數的區別可參考 [Zurich HF2 官方說明](https://docs.zhinst.com/hf2_user_manual/functional_description/lock_in.html)。

## 重現與驗證範圍

在 `03_software` 執行 `node test_correction.cjs`、`node test_ui.cjs`、`node test_calibration.cjs` 與 `python test_software.py`。測試包含固定背景、額外未知同頻干擾、相位變化、弱／零參考、重複 ID、開機／設定失效、原始值保留、標籤／匯出來源與不等間隔 EMA；使用的全是合成資料。`test_ui.cjs` 是 DOM／API 測試環境，並非真正瀏覽器外觀檢查。依原操作手冊重新編譯韌體與 LittleFS，私人金鑰不可放入公開檔案。編譯與瀏覽器測試不能證明 ADC 有足夠餘裕、相位／光學背景穩定或細胞偵測成功。
