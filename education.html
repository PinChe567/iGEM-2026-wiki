Education

We didn’t want people to just hear about science. We wanted them to question it.

AeroSense Education is built around interactive learning. Games, workshops, and public dialogue are named channels; only the Learning Lab is live on this wiki. The aim is that people can question a sensing claim — and that learning can be measured when evidence exists. This page is the documented story for judges and future teams. It is not the course.

Framework

Education philosophy

A talk can transfer a sentence. It cannot tell us whether the sentence survived. We treat education as a loop that has to leave a trace — in a learner’s next decision, or in ours.

Learn

Expose the idea. Put the claim in front of someone before asking them to defend it.

Model

From outreach to mutual learning

Reaching people is a logistics fact. Learning is a change fact. We refuse to treat the first as the second.

Old model

  1. We teach
  2. → audience listens

Our model

  1. We teach
  2. ↕ participants question
  3. ↕ we measure learning
  4. ↕ feedback changes education
  5. ↕ insights inform project communication / design

Education is not successful because we reached people. It is successful only if something changed — for them or for us.

Product

Interactive Learning Platform

Five modules. Same pre/post concepts inside each module. Knowledge gain is post percentage minus pre percentage, stored in the browser, and not treated as a published class result. Item IDs are stable so a survey or a game can later use the same questions.

Open, free, no login. Progress does not leave the device unless an approved backend is added later.

Every activity on this page uses one evidence loop — Question, Design, Engage, Evidence, Learn, Change, Reuse — so games, workshops, this platform, and teacher materials can be compared without a new template each time. Evaluation

Did people actually learn?

We can describe the instrument. We cannot describe a cohort we have not published.

Layer What it is Status
Completed data No identified sample, no published pre/post table, no item-level correction rates. None published
Ongoing data Optional localStorage in each visitor’s browser (aerosense.learn.v2), including reflections. Visible only to that visitor on the dashboard. Local only · not a study dataset
Planned analysis Same-concept items across survey, game, and Learning Lab. Cross-tool comparison of the three mycotoxin misconceptions. Requires consent, minimization, and an approved backend before any upload. Planned
How the platform scores a module

Each module uses three items. The same item IDs appear on pre-test and post-test. Score is the percent of those three answered to the keyed choice. Knowledge gain is post percentage minus pre percentage, reported as percentage points — not “percent smarter.”

Item-level misconception correction is designed (especially Module 2) but not published as a table.

Cross-tool: ITEM_BANK in js/learning-data.js tags each item with sources survey, game, and learning-platform. Survey and game implementations are not on this wiki yet. Only the Learning Lab path is live.

Knowledge gain is evidence of change on these specific questions. It should not be presented as a complete measurement of scientific literacy.

Privacy: no names, emails, or learner IDs are collected by the Learning Lab. See Safety · Data and privacy.

Reflection

What we would do differently

  • We have not yet left the wiki. Zero verified face-to-face programs. High-school, primary, teacher, older-adult, and industry groups are absences, not audiences.
  • LocalStorage is not a study. A visitor’s pre/post pair cannot be reported as our education result. We still lack consent, a sampling frame, and an approved collection path.
  • Games outran evaluation. Odor Pixel Suite exists as a local prototype with unfinished licenses. Shipping it as “play” without a facilitator guide would have been a catalogue, not education.
  • English-only public materials. No bilingual packet. That excludes learners we should have planned for earlier.
  • Item IDs are ahead of the survey and the game. The cross-tool design is real; two of three experiences are not. That is a bias toward the format we could host statically.
  • What a future team should improve: confirm one partner audience before adding channels; evaluate one misconception across two formats before building a third; host only licensed games; publish a CC-licensed facilitator packet; log iterations in the Notebook; never photograph identifiable minors without permission.
