Candidate contribution packages

Each package below is tied to active AeroSense tracks. A project outcome counts as a contribution only after it is packaged so another team can reuse it without private coaching.

Biological construct and part documentation

Status In development

What exists now: Design intent for OR–IRES–mCherry and GCaMP–Orco style constructs, informed by published heterologous insect-OR cell lines [1] Zboray et al., 2023 — full entry in References & Credits. . Local wiki scaffolding lives on Parts and Design. No AeroSense Registry IDs, sequence dumps, or reviewed part pages are published yet.

What remains: Final sequences, maps, characterization summaries, Registry submissions with real part IDs, and a reuse README stating chassis, safety level, and known limitations.

How another team would adapt it (once Available): Clone or order the documented parts, confirm sequences against the released files, and follow the linked assay package before claiming function. Do not treat wiki prose alone as Registry documentation.

Receptor-screening or assay protocol

Status In development

What exists now: Planned VUAA1 functional-control workflow and VOC/agonist imaging concept described on Description and scaffolding on Experiments. No step-by-step, tester-reviewed protocol package is released.

What remains: Materials list with units, transfection and stimulation steps, control matrix, example analysis, troubleshooting, and a non-author test of the written instructions.

How another team would adapt it (once Available): Meet biosafety prerequisites for HEK293T work, run the control set before target VOCs, and record deviations. Adapt concentrations and imaging hardware only after reading the package’s stated operating range.

Reusable fluorescence-processing / model code

Status In development

What exists now: Conceptual AL-inspired normalization/inhibition and MB-inspired sparse projection pipeline described on Description and scaffolding on Model. No public repository, sample dataset, or runnable entry-point is released.

What remains: Source code with dependency pin, README, example input/output, baseline comparisons, license file, and a smoke-test command that a second person has run.

How another team would adapt it (once Available): Install the stated environment, run the example on the bundled sample matrix, then replace inputs with their own receptor time series while keeping provenance notes.

Photodiode / multiplexed optical hardware package

Status In development

What exists now: System intent for excitation, filtering, photodiode / TIA / ADC acquisition, and edge interface on Description and scaffolding on Hardware. Component choices are still being reconciled; no reviewed design-file bundle is released.

What remains: Design files (schematic/layout/enclosure as applicable), BOM with units, firmware or acquisition notes, crosstalk/noise validation procedure, and a license for reuse.

How another team would adapt it (once Available): Reproduce the optical path on the bench with the validation procedure before connecting living samples; document any substituted parts and their effect on noise floors.

Educational materials

Status In development

What exists now: Wiki scaffolding on Education. No workshop packet, slide deck, or classroom module has been released for reuse.

What remains: Learning goals, facilitator notes, source list, accessibility check, and a license statement. Materials must not present planned AeroSense performance as measured fact.

How another team would adapt it (once Available): Obtain the packet from the stated reuse link once Available, keep attribution, and localize examples while retaining the status labels that separate literature, design intent, and results.

How to reuse our work

No downloadable contribution package is Available yet. When a row in the glance table moves to Available, use the following checklist. Do not treat placeholders or wiki scaffolding as a finished release.

  1. Confirm status. Only reuse resources marked Available on this page. In development / In review / Not yet released items are not ready for external adoption.
  2. Prerequisites. For wet-lab packages: institutional biosafety approval appropriate to HEK293T and any VOC/agonist handling. For code: the stated language/runtime. For hardware: basic optics and electronics bench capability.
  3. Obtain files from the stated reuse link. Prefer the package README’s canonical URL. The intended team host is gitlab.igem.org/2026/nthu once it contains reviewed release artifacts. That host is not Available today.
  4. Expected outputs. Each Available package must state its expected outputs explicitly (for example: confirmed sequence file, control fluorescence traces, model metrics table, or optical noise-floor log). If those outputs are missing from the package, stop and contact the team.
  5. Known failure modes to watch for. Incomplete Registry records; missing vehicle/VUAA1 controls; unpinned software dependencies; optical excitation bleed-through; undocumented unit conversions; and instructions that only the original author can follow.
  6. Support / contact. Questions about reuse packages: aerosensebio@gmail.com. Include the package name and the status shown on this page.

What this contribution does not claim

  • It does not claim that a finished reusable contribution already exists because a proposal was written.
  • It does not claim AeroSense performance numbers, disease detection, or field readiness as community resources.
  • It does not claim Registry parts, DOIs, repositories, versions, file sizes, or external reuse stories that have not been verified.
  • It does not treat project-specific lab progress as a contribution unless that progress is packaged for others.
  • It does not mark any resource Available without a resolving link and content review.

Relationship to Engineering

Bronze Contribution asks whether AeroSense leaves something reusable for future teams. Silver Engineering Success asks whether AeroSense documented its own design–build–test–learn cycles with evidence. Those criteria are distinct: a polished DBTL story is not automatically a contribution package, and a released protocol is not automatically Engineering Success.

Engineering cycles, iterations, and decision records belong on Engineering. When a DBTL artifact is later packaged for reuse, it should appear in the glance table here with its own status and reuse link.
